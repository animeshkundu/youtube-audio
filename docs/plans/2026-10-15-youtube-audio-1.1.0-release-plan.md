# YouTube Audio 1.1.0: final plan (v2, post adversarial review)

> Status: approved 2026-10-15. Recovered 2026-10-16 from the working session record after the
> planning session ended before the plan was saved to disk. Content is verbatim from that record;
> only the trailing save-offer sentence was removed. Checkpoint status is tracked in
> `docs/history/` handoffs and the specs each item names.

One release, built in risk order, validated against real evidence before anything is promised. This revision folds in every accepted finding from the independent technical and product reviews, corrects the items they falsified, and adds the missing diagnosis gate.

## 1. Locked decisions

| Decision          | Choice                                                                                                                                                            |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Release shape     | Single listed release, **1.1.0**, with a conditional: if step 0.0 proves users are broken today, a minimal forward patch goes out first (see section 9)           |
| Core health first | CP0 (diagnosis) and CP1 (protection) precede all features                                                                                                         |
| Live fallback     | Lowest-available-quality cap, default on, toggle in options (your call; reviewers preferred opt-in, mitigations below)                                            |
| Idle-nag defeat   | Default on while background play is enabled, toggle in options (same note)                                                                                        |
| Scope model       | Per-tab override only for v1; per-page and per-site grouping are non-goals                                                                                        |
| Competitor reuse  | GPL/MIT sources: ports with provenance. Proprietary Music Mode: behavior captured as a spec, re-implemented by a different agent than the one who read the source |

## 2. What changed since the last revision (review corrections)

1. **Client order inverted.** VISIONOS 1.02 becomes primary, ANDROID_VR 1.65.10 demoted to probe-only fallback, superseding the ANDROID_VR invariant in `CLAUDE.md:20` and `AGENTS.md` via ADR-0012.
2. **Canary truth added.** Verified: the nightly job has failed at the probe step on every sampled run since 2026-07-11 while the workflow reports success (`continue-on-error`). It is now a deliverable to unmask, correctly target, and run locally; not a premise.
3. **Diagnosis gate added (0.0).** Reviews on 2026-08-07 and 2026-08-16 predate the 2026-08-17 client degradation, and the repo's own qualification plan flags the update-consent path as the largest unknown. Cause must be discriminated before a fix is chosen.
4. **Three work items reworked.** Web Audio "disconnect on dispose" is impossible (capture is permanent; bypass instead). `downloads` optional is impossible on Fenix (API removed); desktop-only. `/next` filtering stays (ad coverage per SPEC-004).
5. **Coexistence upgraded from heuristic to spike plus policy.** The `scriptlets.ts` foreign-hook check false-positives on stock YouTube; Firefox chains response filters but unordered, so pruning becomes idempotent and a two-extension bench spike proves behavior.
6. **Release mechanics corrected.** AMO is forward-only: no re-sign, no revert; a rehearsal and a forward-patch runbook replace the rollback wording. Beta lane (dormant since 2026-07-13) gets revived before it is trusted.
7. **Compliance fixed now, not at release.** `amo-metadata.json` says "Collects nothing" while the manifest declares `websiteContent` (`wxt.config.ts:131`); that wording is editable on AMO immediately and is the 1.0.3 rejection class.

## 3. Invariants and how this release touches them

Logged-out only, credentialless (`credentials: "omit"`), `PlayerHandle` the sole `src` writer, four content-script matches never widened (embeds use `all_frames`), fail open everywhere, bridge carries booleans and bounded codes only, MV2 ships and MV3 stays buildable. The release changes exactly two documented positions, each via ADR: the client table (ADR-0012) and the scope/status state model (ADR-0013). Everything else is compliant by construction.

## 9. Release mechanics

1. **Conditional rule (unchanged in spirit, sharper):** if 0.0 shows users broken now, cut a forward patch the same day containing only the proven fix slice (consent and/or 0.2 rotation), then continue. Otherwise straight to 1.1.0.
2. **Gate:** `npm run validate`, hermetic bench, settings matrix, mobile hermetic lane, strengthened canary run locally with a recorded green baseline, manifest declaration tests, MV3 build, `web-ext lint`.
3. **Beta soak:** revive `beta.yml` (dormant since 2026-07-13) by signing `1.1.0b1` unlisted on the same ID; hand-install desktop and Android; several days with local canary runs.
4. **Publish rehearsal and runbook:** dry-run `publish-amo.yml`, verify the guard/environment and how 1.0.4 actually reached AMO, then publish listed on demand. Rehearse the **forward-patch runbook**: pre-bumped patch version, prepared release notes, `amo-production` approval, expected listed review of days to weeks for a version with permission changes; "disable listing" is the extreme lever, not a rollback.
5. **Post-publish:** answer new reviews, watch canaries, monitor for a new failure cluster, close the hygiene items that were gated on the release.

## 10. Risks and decision rules

| Risk                                               | Mitigation                                                                                                   |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Users broken now and it is consent, not the client | 0.0 discriminates first; consent fix becomes the patch slice                                                 |
| VISIONOS shape/fields differ from expected         | Audit probe asserts a real >8 MiB download before the gate; ANDROID_VR retained as probe fallback            |
| uBO chaining order unspecified                     | Idempotent pruning, two-extension bench spike, fail-open, ADR-0014                                           |
| Idle-nag and fallback defaults are the fragile two | Toggles, bounded observers, fail-open, canary watch, copy updates; flip to opt-in is a one-line escape hatch |
| Embed frame model surprises                        | Spec frame ownership before code; embeds global-only                                                         |
| Finish "green" on an untruthful canary             | Canary must be truthful and locally baseline-verified before it is cited as evidence                         |
| Beta lane dormant                                  | Revive and exercise it before relying on it                                                                  |
| AMO review latency                                 | No promised date; patch runbook ready; metadata fixed early                                                  |

## 11. Non-goals

Per-page override; per-site YouTube versus YouTube Music groups; true audio-only live streams; other platforms; Chrome port; remote config or rules; remote diagnostics (stays local and PII-free).

## 12. Definition of done

Each checkpoint above ships with its spec, unit tests at the 90 percent bar, bench or matrix coverage for its runtime surface, and a history handoff. The release is done when: 0.0's diagnosis is written and its fix slice verified, the local canary is green with strengthened assertions, the gate is green, the beta soak is real, metadata and data-flow docs are consistent, runbooks are rehearsed, and the five reviews are answered.

**First 72 hours:** 0.0 diagnosis spike and AMO replies; 0.1 canary truth and local baseline; H1 metadata wording fix on AMO. Then the client verdict decides whether the patch slice fires, and 0.2 plus 2.1 begin immediately after.
